# Base segmentation (v117) vs proofread labels (v1412): data-access map and real structure

This note characterizes how the MICrONS **Minnie65** base segmentation relates to
the proofread labels, and exactly which HTTP endpoints we can reach **without
`caveclient`** (which will not install in this container). All probes below were
run with plain `requests` + the public CAVE bearer token
(`a08cdcba8581846f48d5742a75c53311`), the same pattern as
`neuronauts/data/loaders.py`. Reproduce with `scripts/probe_seg_mapping.py`.

Date of probes: 2026-06-12. Datastack: `minnie65_public`.

---

## 1. What "v117" and "v14xx" actually are

They are **materialization versions**, not segmentation source versions. Each is
a named snapshot of the proofreading/agglomeration state at a specific timestamp.
Confirmed from the materialization version-metadata endpoint:

| Version | Timestamp | Status | In public versions list? |
|--------:|-----------|--------|--------------------------|
| **117** | `2021-06-11T08:10:00.215Z` (unix `1623399000`) | `AVAILABLE`, `valid=True`, `is_merged=True` | yes |
| **1412**| `2025-04-29T10:10:01.200Z` | **`EXPIRED`** (expired 2026-05-10), `valid=False` | **no** |

Public materialization versions currently advertised: **`[117, 943, 1300, 1507,
1621, 1718]`**. Note **1412 is no longer in the list and its tables are
expired** — its annotation/materialization tables are no longer queryable.

So in this repo's pipeline language:

- **v117** = the *early/raw* segmentation state (~mid-2021). This is the "noisy
  scaffold" with split errors (one neuron fragmented across many roots) and merge
  errors (one root spanning multiple cells). It is the `seg_version` /
  `base_root_id` space in `neuronauts/schemas.py`.
- **v1412** = a *later, more-proofread* state (~2025-04). This is the
  `label_version` / ground-truth space. The proofread **nucleus table** for
  v1412 is still available as a static CSV on GCS (used by
  `loaders.load_nucleus_table`), even though the live materialization tables for
  1412 have expired.

The mapping v117↔v1412 is a **chunkedgraph lineage** relationship: the same
physical supervoxels are agglomerated differently at the two timestamps. You map
between them by resolving supervoxels (or L2 nodes) to their root id *at a chosen
timestamp* — exactly what `path_dataset.py` does with
`get_roots(svids, timestamp=past_dt)` and `get_delta_roots`.

The segmentation *source* (image/voxel geometry) is a single graphene volume:
`graphene://https://minnie.microns-daf.com/segmentation/table/minnie65_public`.
v117 and v1412 are two readings of the **same** graphene table at two timestamps.

## 2. Data access over plain HTTP (no caveclient)

Discovered base URLs (from the datastack info response):

- **CAVE info (global):** `https://global.daf-apis.com`
- **ChunkedGraph + Materialization (local_server):** `https://minnie.microns-daf.com`
- **Segmentation table id:** `minnie65_public`

### Confirmed WORKING (HTTP 200 with bearer token)

| Purpose | Method + URL | Result |
|---------|--------------|--------|
| Datastack info → discover servers/table | `GET https://global.daf-apis.com/info/api/v2/datastack/full/minnie65_public` | 200, JSON |
| List materialization versions | `GET https://minnie.microns-daf.com/materialize/api/v2/datastack/minnie65_public/versions` | 200 → `[117, 943, 1300, 1507, 1621, 1718]` |
| Version metadata (timestamp) | `GET …/materialize/api/v2/datastack/minnie65_public/version/{v}` | 200, gives `time_stamp`, `valid`, `status` |
| **Root → L2 nodes** | `GET …/segmentation/api/v1/table/minnie65_public/node/{root_id}/leaves?stop_layer=2` | 200 → `{"leaf_ids":[…]}` |
| **Root → supervoxels** | `GET …/node/{root_id}/leaves?stop_layer=1` | 200 |
| **Supervoxel → root (current)** | `GET …/node/{svid}/root` | 200 → `{"root_id":…}` |
| **Supervoxel → root @ timestamp (v117!)** | `GET …/node/{svid}/root?timestamp=1623399000` | 200 → v117 root id |
| **Batch supervoxels → roots @ timestamp** | `POST …/table/minnie65_public/roots_binary?timestamp={unix}` body = LE `uint64[]` of svids, resp = LE `uint64[]` of roots | 200 |
| Nucleus table (v1412, static) | `GET https://storage.googleapis.com/mat_dbs/public/minnie65_phase3_v1/v1412/nucleus_detection_v0_merged.csv.gz` | 200 (no auth) |
| Skeleton cache | `GET https://minnie.microns-daf.com/skeletoncache/api/v1/minnie65_public/precomputed/skeleton/{root_id}` | 200 (per loaders.py) |

This is the headline result: **the timestamp-addressable chunkedgraph fully
exposes the v117↔v1412 mapping over plain HTTP.** We do not need caveclient to
characterize merge/split structure — `get_roots(svids, timestamp=...)` is just a
binary POST to `/roots_binary`.

  table but I did not probe them directly (the `/leaves` + `/roots_binary`

- Whether `/roots_binary` enforces a max batch size (I used ≤4000 svids/request

## 3. Real numbers obtained

Sampled v1412 root ids from the public nucleus table and queried the
chunkedgraph live.

**L2 components per v1412 neuron** (n=5, `leaves?stop_layer=2`):

```
864691135429444926:   313 L2 nodes
864691136194630988:   600
864691135480521168:  2870
864691136090135607:  4068
864691135748985641:  6639
                     min=313  max=6639  mean≈2898
```

A v1412 neuron is built from hundreds–thousands of L2 nodes (and far more
supervoxels — individual neurons had 60k–1.15M supervoxels in the sample).

**Single supervoxel, current vs v117 timestamp** (direct proof the mapping
differs across versions):

```
svid 97407866213898401
  → current root  864691136090135607   (v1412)
  → @1623369600   864691135538371698   (v117)   ← different agglomeration
```

**Split structure** — for a sample of v1412 neurons, how many *distinct v117
roots* did their supervoxels trace back to (subsampling ≤4000 sv/neuron, mapped
via `/roots_binary?timestamp=1623399000`):

```
v1412 root            n_sv   distinct_v117_roots   top-5 mass share
864691136946673375    61721         1              [1.00]
864691136272961982   157449         1              [1.00]
864691136974435100   859658         1              [1.00]
864691136022254584  1151420         1              [1.00]
864691136057285080   596572         1              [1.00]
864691135762421302   443039         1              [1.00]

864691136176316166   978065        10              [0.93, 0.06, 0.01, 0.01, 0.00]
```

Round-trip check on the 10-root neuron: mapping its supervoxels to the **current**
root returns `864691136176316166` for 1000/1000 svs (consistent lineage).

**The single most important real finding:** for *soma-anchored* (nucleus-table)
neurons, the v117→v1412 change is **dominated by one large v117 root plus a long
tail of tiny fragments**, not by many equal-sized pieces. 7/8 sampled neurons
already existed as essentially **one** v117 root (these somata were well
segmented even in 2021); the one split-fix case stitched 10 v117 roots but ~93%
of the mass came from a single dominant root and the other 9 were small
fragments. In other words, real split-fixes look like *one trunk + slivers*, and
they are **far less common among soma-containing roots** than a synthetic
benchmark with uniformly-sized fragments would assume. (This sample is biased
toward well-proofread cells because it is drawn from the nucleus table; the
fragment/merge population lives in the *non-soma* roots — see plan below.)

## 4. Plan to characterize merge/split statistics with full access

Prioritized, all achievable over the HTTP endpoints proven above (no caveclient):

1. **Split statistics (one v1412 neuron ← many v117 roots).**
   For each of N sampled v1412 neurons: `leaves?stop_layer=1` → all supervoxels;
   `POST /roots_binary?timestamp=1623399000` to get v117 roots; histogram the
   number of distinct v117 roots and their mass shares. *Do NOT subsample* for
   the real run — use the full supervoxel set in ≤4000-id batches. Report the
   distribution of `n_v117_roots` per neuron and the fraction of mass in the
   dominant root. **Sample both soma neurons (nucleus table) and random
   non-soma roots**, because the nucleus table is biased toward clean cells.

2. **Merge statistics (one v117 root → many v1412 neurons).**
   Pick v117 roots (e.g. the dominant roots from step 1, or roots sampled at the
   v117 timestamp), get their supervoxels *as of v117*, then map those
   supervoxels to **current** roots (`/roots_binary` with no timestamp). If a
   single v117 root's supervoxels split across ≥2 current roots, that is a
   merge-error fix; quantify how many current neurons each v117 root spans and
   the size split. To enumerate v117 roots properly, use `get_delta_roots`
   /`/delta_roots` between the v117 timestamp and now.

3. **Size + spatial distribution.**
   For each merge/split event, attach L2-node counts (proxy for volume) and the
   centroid of the involved supervoxels (supervoxel ids are spatially chunked;
   or pull L2 centroids from the L2 cache). This gives "how big" and "where" the
   corrections concentrate (e.g. near somata vs distal axon).

4. **Operation-level ground truth (optional, higher fidelity).**
   Probe `tabular_change_log_many` / `lineage_graph_multiple` / `past_id_mapping`
   to read the actual proofreader edit log (merge vs split op, timestamp, who).
   This converts the inferred statistics in steps 1–2 into exact per-edit counts.
   These endpoints are untested here but exist in the CAVE endpoint table.

5. **Scale-up hygiene.** Batch ≤4000 svids/POST, ~0.2–0.3 s between requests,
   single-threaded or low concurrency (mirror `loaders._INTER_REQUEST_DELAY`).
   Cache `(svid → v117 root)` and `(svid → current root)` to disk; the
   supervoxel→root lookups are the cost center.

### Caveat that shapes the benchmark
Because v1412's materialization tables are **expired**, you cannot pull v1412
*synapse/annotation* tables anymore — only the static nucleus CSV plus the live
chunkedgraph lineage. For synapse-anchored work, use an **available** version
(`1300`, `1507`, `1621`, or `1718`) as the "proofread" target instead of 1412;
the chunkedgraph mapping machinery is identical, just swap the timestamp.
